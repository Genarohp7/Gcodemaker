## Users

GCodemaker opera una web publica de servicios digitales y, dentro del mismo ecosistema, una herramienta privada llamada GC Broadcast. La primera cuenta cliente es Centro de Actualizacion y Capacitacion Profesional (CACP). Los usuarios principales son personal administrativo que necesita preparar campanas de WhatsApp, revisar consumo mensual y consultar historial sin lenguaje tecnico.

## Product Purpose

GC Broadcast permite gestionar campanas de mensajeria masiva por WhatsApp para empresas cliente. En esta etapa el objetivo es construir el cascaron visual y estructural: rutas privadas, pantallas, formularios, tablas, estados y datos mock preparados para una futura integracion con backend, PostgreSQL y WhatsApp Cloud API.

## Brand Personality

Claro, confiable y operativo. La experiencia debe sentirse como un SaaS privado de GCodemaker: profesional, ordenado y facil de usar para administracion.

## Anti-references

No debe parecer una landing publica, un demo tecnico improvisado ni una consola para desarrolladores. En vistas del cliente se evitan terminos como API, webhook, token, endpoint y payload. No debe aparecer enlazado desde la navegacion publica del sitio.

## Design Principles

- Priorizar el flujo administrativo: crear campana, cargar contactos, revisar vista previa, confirmar y monitorear estado.
- Mostrar capacidad y consumo con claridad antes que con decoracion.
- Separar vistas de cliente y administracion interna de GCodemaker.
- Preparar la arquitectura visual para multiempresa sin duplicar pantallas por cliente.
- Mantener lenguaje humano y operativo en todas las acciones visibles.

## Accessibility & Inclusion

Usar controles estandar, foco visible, contraste suficiente, textos escaneables y layout responsive. Evitar depender solo del color para comunicar estados de consumo o alertas.
